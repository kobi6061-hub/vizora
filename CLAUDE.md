# Repository layout

- Repo root = the **PROPX** private dashboard (formerly KobiX RealEstate), deployed to Vercel as-is
  (static `index.html` + `login.html`, Edge `middleware.js` auth gate, `api/` login/logout,
  `vercel.json`). No build step; framework preset must stay "Other"/none.
- `vizora-app/` = the earlier VIZORA Next.js product (self-contained; see its own CLAUDE.md).
- `standalone/` = offline/artifact build of the dashboard, generated by
  `scripts/build-standalone.py` from the root `index.html`. It embeds no password/credential (the
  repo is public); the build script refuses one.
- `scripts/` = KobiX tooling (`kobix-dev-server.mjs` local auth simulation, `build-standalone.py`,
  `gov-sync.js` government-data sync CLI).
- `lib/gov/` + `api/gov/` + `data/gov/` + `test/gov.test.js` = the government real-estate
  data layer (provider architecture, normalized transaction schema, snapshots; see `lib/gov/README.md`).
- `lib/geo/` + `api/geo/` + `data/geo/` + `scripts/build-geo-registry.py` + `scripts/geo-audit.js`
  = the national geography registry (every official locality + street, canonical codes, search API,
  coverage audit).
- `test/integrity.test.js` = P0 data-integrity gates over `index.html` and the standalone build (no
  synthetic street layer, generated history, invented medians or sample-size confidence; OFFICIAL only
  with stored provenance; no ranking over non-official values outside the capital section's labelled
  MODEL RANKING; no embedded credential; no approximate `NATIONAL_CURVE`; capital outside surfaces —
  command-bar signal, map layer, gold markers, profile shortcut, insights teaser — stay off via
  `CI_EXTERNAL=false`).
- `test/capital.test.js` = the capital module (`#capital`, `@ci-engine` block run on the real board
  data): equity accounting (value − debt + tax/costs = equity used; used + unused + reserve = capital),
  caps/capacity/pool/minimum data basis, rankings independent of capital size and of the appreciation
  assumption, every return a true IRR from `calcEngine`/`calcIrr`, data basis from `vcOf` (no o-flags),
  every policy rule and assumption editable in the section.
- `test/calculator.test.js` = the deal calculator (`#calc`, `calcEngine`, `calcIrr`): visible,
  independent of the capital model, missing inputs → UNAVAILABLE (never defaulted), no silent
  appreciation.
- `lib/market/` + `scripts/market-sync.js` + `data/market/` + `.github/workflows/market-sync.yml` +
  `test/market.test.js` = the daily official-indicator sync (Bank of Israel rate, CBS new-homes index; optional monthly
  CBS series found by name: construction inputs 200010, CPI 120010, CPI rent component 120460 — a failure there is
  recorded, never fatal) feeding the market tape; `data/market/` is written by the scheduled workflow, not by hand
  (see `lib/market/README.md`).

- `lib/housing/` + `api/housing.js` + `data/housing/` + `scripts/housing-sync.js` + `test/housing.test.js`
  = government (subsidized) housing: the official מחיר למשתכן / מחיר מטרה lottery records (data.gov.il,
  Ministry of Construction and Housing) — normalized, upserted on the official LotteryId, never deleted,
  status history, raw snapshots; served paginated by `GET /api/housing?view=…` and shown in the page's
  `#housing` section (see `lib/housing/README.md`). Missing factual values render "—" (class MISSING / חסר).
  `scripts/housing-discover.js` + `.github/workflows/housing-discover.yml` = read-only source discovery.
- `lib/land/` + `api/land.js` + `data/land/` + `scripts/land-sync.js` + `.github/workflows/land-sync.yml` + `test/land.test.js`
  = Land & Tender Intelligence (`#land`, "קרקעות ומכרזים"): the Israel Land Authority's tender site API (list + per-tender
  detail on a daily budget + map centroids) normalized per MichrazID with lifecycle from the Authority's status codes
  (published ≠ open ≠ closed ≠ decided ≠ awarded — awarded only with a winner name and an award sum or winning bid), track
  from type/purpose/population codes, per-lot economics with their basis and VAT "not stated", exact joins only (xplan
  plan number; RMI planning inventory — STALE 2022, state land only; MoCH construction progress by block/parcel). Slim
  records in `tenders.json` (with `lotRefs`), lots in `lots-<year>.json` shards, history, raw list snapshots; Supabase `land_*` tables
  (`supabase/migrations/20261004120000_land_tenders.sql`). `lib/land/coverage.js` counts detail coverage (the page tags
  every figure FULL LIST / PARTIAL DETAIL / DERIVED SUBSET); `lib/land/lineage.js` links re-tenders only through the
  Authority's lot file id (TikID) and counts the unique pipeline once per lot; the page defaults to the CURRENT market
  (`scope=current`). Not subsidized-housing lotteries, not transactions (see `lib/land/README.md`). `scripts/land-discover.js` + `.github/workflows/land-discover.yml` = read-only discovery.
- `lib/planning/xplan-units.js` + `lib/planning/README.md` + `test/xplan-units.test.js` = the ONE definition of the XPlan
  housing-unit pair (audit 13.10.2026): `pq_authorised_quantity_120` = units authorised BEFORE the plan
  (`existingAuthorisedUnits`), `quantity_delta_120` = the plan's change (`planUnitDelta`), units after the plan = their sum
  (DERIVED, `unitsAfterPlan`); raw values kept; never "approved units". Land (read model only — stored records and their
  Supabase copy unchanged) and renewal read units only through it.
- `lib/gov/providers/overDeals.js` + `test/republished.test.js` = the deals source in use since 02.10.2026 (owner's
  decision): the Tax Authority register as republished by גרסאות לעם (over.org.il) — not a government channel, labelled so
  on the page (never "official source"); a copy dated by `scraped_at`; address only via the parcel crosswalk; partial sales
  never priced; `GET /api/gov/transactions` pages it (`offset` + `level`) and says who delivered (`meta.deliveredVia`) and
  claims a sync only when a source answered (`meta.sourceAnswered`). GovMap (403 to the server) and the Tax Authority
  connector stay first in line.
- `lib/gov/ledger.js` + `scripts/tx-sync.js` + `data/transactions/` + `test/ledger.test.js` = the
  transaction ledger: daily refresh + 120-day rolling backfill, upsert on the record key (official id, or
  fingerprint + occurrence), `first_seen_at` kept, nothing deleted (see `lib/gov/README.md`).
- `.github/workflows/data-sync.yml` = the daily housing + transaction sync; `data/housing/` and
  `data/transactions/` are written by it, not by hand.
- `supabase/migrations/` = the PROPX Supabase schema: `market` (public market truth: sources, sync runs,
  raw snapshots, geo links, transactions, housing lotteries + status history) and `user_state` (future
  per-user state, kept apart). Only the dedicated PROPX project; the sync writes there when
  `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` are set as server-side secrets.
- `lib/gov/tx-refresh.js` + `api/jobs/tx-refresh.js` + `.github/workflows/tx-refresh.yml` = the transaction
  refresh core shared by the GitHub job (`scripts/tx-sync.js`) and PROPX's own Vercel runtime (token-protected,
  fail-closed `POST /api/jobs/tx-refresh?mode=probe|sample|run` — PROPX_JOB_TOKEN or a verified GitHub OIDC token of this
  repo's production-branch job workflow, `lib/gov/oidc.js`; `middleware.js` lets exactly that path — and no other
  `/api/jobs/…` — past the session gate). A window is `complete` only when the sweep proves it;
  refused/timeout/cap/partial never are. `lib/store-config.js` validates the store env and redacts it from any text.
- `supabase/` = migrations + `supabase/README.md` (activation steps for the dedicated PROPX project, secret names
  and where they go); `scripts/supabase-verify.js` + `.github/workflows/supabase-verify.yml` verify it. Store of
  record: Supabase once configured; `data/housing/` is the bundled fallback (`freshness.store` says which served).

- `lib/entities/` + `lib/trust/` + `api/intel.js` + `test/entities.test.js` = Developers & Projects (`#intel`, "יזמים
  ופרויקטים") and the Data & Trust Center (`#trust` inside `#sources`): a deterministic registry over the stored ILA
  tender records and MoCH lottery records, labelled OBSERVED PROPX ACTIVITY (never a land bank or total pipeline). One
  developer = one canonical name (typographic variants only); no similarity merge — same-letters / cut-prefix names are
  linked as "possibly the same", never combined; unmarked winners (private persons) counted, never listed. Projects keep
  their own ids (`moch:<ProjectID>`, `ila:<MichrazID>:<lot>`) and are never joined across sources; units never added
  across sources. One search routes tender / plan / parcel / developer / project / locality / street / address to its
  entity (also in the command bar). `lib/trust/catalog.js` = every source with its latest check from the run logs in
  one vocabulary (SUCCESS / UNCHANGED / PARTIAL / REFUSED / FAILED / SCHEMA_CHANGED / STALE / NO_RUN). See
  `lib/entities/README.md`.

- `lib/renewal/` + `scripts/renewal-sync.js` + `.github/workflows/renewal-sync.yml` + `data/renewal/` + `test/renewal.test.js`
  = urban renewal: the Ministry of Construction and Housing's urban-renewal complexes (data.gov.il `urban_renewal`,
  resource f65a0daf…) — read whole daily, upserted on the complex number (never deleted), every changed field in
  `history.jsonl`, raw snapshot per content hash; the Ministry's status kept verbatim beside a mapped stage; the
  declaration state per row (declared / not yet declared / not stated); units as published (additional ≠ net in every
  row). Served by `GET /api/intel?view=renewal|renewalComplex` and shown as the "התחדשות עירונית" tab of `#intel`. A
  declared complex is not construction and is never attributed to a developer; `data/renewal/` is bot-written (see
  `lib/renewal/README.md`). `lib/renewal/planning*.js` + `scripts/renewal-planning-sync.js` + `test/renewal-planning.test.js`
  = the exact XPlan join (Planning Administration online-plans layer): plan number, then the Mavat main-plan id in MoCH's
  own link (= `mp_id`); contradicting keys → ambiguous; never by name or geometry; stage from the layer's own status
  strings only (approval ≠ permit ≠ construction); MoCH and XPlan values side by side with every disagreement flagged;
  `data/renewal/planning*.json` + `plan-geometry.json`; shown as the tab's planning strip and the drawer's PLANNING STATUS.

- `altaris/` + `test/altaris.test.js` = the ALTARIS Capital Allocation Engine (`/altaris`, one `rewrites` entry in
  `vercel.json`): an isolated institutional underwriting module comparing BUY / FINANCE / HYBRID for a residential deal —
  its own page, styles (PROPX tokens copied, not shared), a pure engine (`altaris/engine.js`: dated monthly cash flows,
  XIRR, MOIC = distributions ÷ invested, break-even / max-price solvers, scenarios + stress presets, explained risk score,
  hurdle-based structure signal), inline-SVG charts and CSV / XLSX / print-PDF / JSON exports. Its only PROPX touch points
  are one rail link in `index.html` (hidden in the offline build), the rewrite and dev-server parity; it reads PROPX data
  GET-only (geo search, transactions, land, housing, market snapshot) and keeps deals / fund settings in the browser
  (`altaris:*` keys) — there is no server-side ALTARIS store yet (see `altaris/README.md`).
  `altaris/methodology.js` = the versioned metric conventions (ALTARIS Metric Methodology v1): pure bilingual data that
  documents the engine (never computes), pinned to the engine's sha256; the page's ⓘ marks → popover → "Metric
  Conventions" view (`#method`), the optional PDF appendix and the Excel "Metric Conventions" sheet all read it.
  `test/fixtures/altaris-baseline.json` freezes engine outputs (zero-drift gate in `test/altaris.test.js`).
  `altaris/cases.js` = five illustrative, synthetic investment cases (inputs only, fictional names, real localities as
  setting); loaded into the ordinary deal screen via "מקרי השקעה"; never saved / in the portfolio / in any PROPX dataset
  unless the user creates a working copy; exports marked ILLUSTRATIVE CASE.

Secrets: `SITE_PASSWORD` / `SESSION_SECRET` live only in Vercel env vars (see `.env.example`).
`SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `PROPX_JOB_TOKEN` live only in GitHub Actions / server env — never
in the repo or the page.
